# Coding implementation

- Identify the requested behavior and actual entry point. Read applicable project instructions, relevant code and tests, and the working-tree state before editing; preserve unrelated changes.
- Trace affected callers, data shapes, error paths, and permissions. Use the project's existing patterns and dependencies unless the task justifies a change.
- Use the selected workspace harness and its actual permissions. A staged edit is pending until approved; verify the resulting file before reporting it as applied.
- Implement the smallest coherent change that completes the request. Keep user-facing behavior clear; avoid fake integrations, hard-coded success, and unrelated rewrites.
- Run focused checks against the real entry point and relevant boundaries. Use representative temporary fixtures for stateful work; distinguish mocked checks from live verification. Broaden checks when risk or failure warrants it.
- Summarize behavior changed, checks and any remaining limitation. External publication, purchases, messages, and destructive actions require the authority already applicable to the task.
